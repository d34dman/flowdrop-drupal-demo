Haiku does not survive the large page

Three different failure shapes on the same input. B5's ReAct node failed outright — the pipeline died after 5.8s and delivered nothing. B6 "completed" in 3.1s by returning exactly 20 bytes: Task is not solvable. B3 started converting, emitted 2.4 KB of navigation chrome, and stopped — 4% of the document. The same three workflows, on the same page, complete on every other model.

B8 and B9: four models, three cells rerun after a runtime fix

B8 gives B5's agent a URL-to-Markdown tool — B7's fix without B7's prompt change. It is two calls on every model and every page; on Sonnet 4.6 it is B7 to within a cent. Opus 5 (run 5 September) tops both panels where it completed: 97% on the small page and 90% on the large, against 76–83% for the other three models on the large page. Its large-page B9 critic accepted the first draft, so B9 took three calls instead of everyone else's seven and cost only 15% more than B8. Both Opus large documents left one mention readable: "Backdrop CMS" in the See-also list, which Sonnet 5 had redacted. B8 on Opus needed the confirmation gate waived to produce the medium page (§). On its first turn Opus asks for two tools at once — the URL-to-Markdown tool and a raw HTTP fetch of the same URL. The HTTP-request node declares side effects, so FlowDrop's confirmation gate paused the run and filed an "Approve?" interrupt for an operator; the benchmark runs unattended, so three attempts sat paused after six seconds and $0.008 each, with identical tool calls and token counts. The gate was working as designed on a redundant call no other model made. With the gate waived on the workflow the cell completed at 99% retention, 56 redactions and 3 leaks — but the redundant fetch is not free: the raw HTML came back as a second tool result, and the cell's 97,768 input tokens and $0.61 are thirteen and ten times Sonnet 5's on the same page. B9 on the same page, whose critic loop ran the tool call singly, completed at 100% retention with 62 redactions and zero leaks. Haiku on the medium page redacted 40 mentions and still left 10 readable — the only B8 cell with leaks in double digits. B9 adds a critic that can send the answer back up to three times. On Sonnet 5 it is the only variant in the matrix with zero leaks on every page; on Sonnet 4.6 the critic accepted the medium draft unchanged and its large-page revisions bought one fewer leak for three times the cost.

Three B9 cells — Haiku small and medium, and Sonnet 4.6 small — are reruns. On the first sweep all three died the same way: the agent revised without calling a tool, and FlowDrop's loop runtime failed the consumer of the tool node instead of skipping it (flowdrop#3592443). FlowDrop fixed it the same day and the cells were rerun on the fixed module. With the loop running to the end, Haiku's B9 has zero leaks on all three pages, at nine calls and four to five minutes each; Sonnet 4.6's three revisions on the small page ended on the same 69% document its B8 run produced.

Haiku also fails quietly, which is worse

On the medium page, B5 on Haiku returned a clean, complete-looking document — 69% retention, nothing visibly wrong — with zero redactions and all 29 competitor mentions intact. It did the conversion and skipped the actual task. A length metric alone would have scored this run as healthy; only the leak count catches it.

Sonnet 5 is the price-performance line

Averaged over the cells all four models completed, Sonnet 5 delivered retention equal to or better than Sonnet 4.6 at roughly half the cost and well under half the wall clock — except on B5, where it summarises. A verification rerun of all three Sonnet 5 B5 cells split that finding in two: the small page reproduced exactly (52% both draws, and a third draw on 5 September returned the byte-identical document at $0.061), but the large page's 44% split: a verification rerun came back at 73% with 4 redactions, in line with Sonnet 4.6, and a third draw on 5 September came back at 45% for $2.24 (‡ in the table). One draw in three keeps the document; two summarise. The B5 deep-dive page carries both observations. Opus 5 buys the top of every retention panel at 2–4× Sonnet 5's price. Haiku is only defensible on B3-medium-sized work, where it is 3–10× cheaper than everything else and does the task correctly.

One anomaly, flagged rather than hidden

The B3 large outputs from Sonnet 5 and Opus 5 are byte-identical (same 64,548 bytes, same MD5), despite different wall clocks (340s vs 422s) and different metered output tokens. The workflow config was verified to point at each model before each pass. Two models producing an identical 64 KB transcription is not credible as coincidence; a response cache somewhere in the chain is the likely explanation. Treat those two cells as one observation, not two.

The 5 September rerun of B5 small on Sonnet 5 (‡ in the table) adds a second sighting: eighteen days after the matrix pass, with a fresh pipeline and a different context uuid, the agent returned the same 3,600 bytes, same MD5 as the 20 August cell, on metered tokens that differ by 3 in and 95 out. That is the same shape as the B3 anomaly and points at the same place in the chain.

Reading these honestly

  • One repetition per cell. n=1 everywhere. Positions are indicative; the findings are the slopes, the collapses, and the leak counts — not second decimals.
  • Retention is a proxy. Both sides are de-noised the same way (link targets and image alt blocks stripped, whitespace collapsed) before byte counts are compared. It cannot tell added prose from preserved prose. The metrics here were recomputed with one pipeline across all four models, so they differ from the sibling plots artifact by under 1%.
  • Small, medium and large are input page sizes (~38 KB, ~164 KB, ~535 KB of raw HTML) — never model tiers. The models are the colours.
  • The Sonnet 4.6 rows for B3, B5 and B6 are the original benchmark runs; their other three models come from the later matrix pass (tags matrix-* in metrics.jsonl). B8 and B9 come from the 5 September sweeps (tags bench89-*; the three B9 cells rerun after the FlowDrop fix carry b9fix-*), which did not include Opus 5; the Opus 5 cells for B8 and B9 were run later the same day (tags bench89-opus5-*). The B8 Opus medium cell plotted is the gate-waived run (tag bench89-opus5-medium-nogate); its three paused predecessors are in the ledger. Sonnet 4.6's B5 large cell requires the 10 MB pipeline-memory patch.
  • Leak terms: WordPress, Joomla, Wix, Squarespace, Contentful, Sitecore, TYPO3, counted case-insensitively.
