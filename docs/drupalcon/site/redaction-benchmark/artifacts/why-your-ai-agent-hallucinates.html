Why Your AI Agent Hallucinates

A sitcom in five episodes — and every episode pays out a field card the audience takes home.

Tue 29 Sep · 13:30 · Mees Room I · 45 min · per episode two photographable slides: the moral, then the field card (Gotcha / Watch for / The fix). Twelve rules total, collected on one Field Guide slide at the end.

Recurring cast

The user
real person; hand-picks colours; asks for “darker”.
The agent
always cheerful, always says Done.
Me
keeps believing the agent; keeps being wrong.
Done — your palette is ready.

The running gag: this bubble reappears, unchanged, after every disaster. By episode three the room says it with you — and it quietly carries the whole thesis: every failure was silent.

04:00

Act I — It worked in the demo

4 min

Thirty seconds of the honeymoon, recorded: chat builds a page, styles a brand, everyone claps. “This is the part you’ve all seen. It’s also the last time today anything works.” One slide on what Atelier and FlowDrop are — sixty seconds, case study not pitch.

The on-ramp (90 s) — for everyone who has never built one of theseTold through our own naive history, not a definitions slide. “Our first agent wasn’t an agent — it was one chat call. Tool results were never fed back in.” An agent is a chat call in a while-loop that feeds tool results back. A workflow engine is that loop drawn as a graph you can look at. Two quick beats from week one: our agent had amnesia — every turn started from scratch, and the transcripts were already in the database, nobody was reading them back; and the first cost surprise — the user types 2+2 and the meter says “3 AI calls · $0.0013”, because one user sentence is never one model call. “That’s the whole mental model you need for the next forty minutes. Now let’s meet the first real user.”

08:00

Act II — Five episodes

~23 min
Episode 1

“Make it darker”

5 min

The sceneThe agent sets the brand green. The user hand-picks yellow. “Make it darker” → a darker green. A week later, same words, different bug: a darker brown. Best line, verbatim from the transcript — the agent looks at her yellow and says “it looks like the blue change from last turn didn’t actually land.” It’s gaslighting her with its own memory.

The twistThe model never hallucinated. Once the prompt carried a remembered value, once no value, once var(--color-yellow-100) — an alias: a colour with no colour in it. Fifteen-second bonus: the model insists oklch(0.98 0.01 0) is white. Show the pink.

Done — your palette is ready.
Never let the model re-type reality. Feed tools ground truth over a wire the model can’t touch.First upstream cameo: we got that wire added to FlowDrop itself.
Field card 1 · ground truth
GotchaAn alias (var(--x)) or an unreadable value (oklch, rem) in a prompt is a value the model can’t reason from — it reasons confidently from the wrong neighbour. An orchestrator restating state restates its memory of state.
Watch forPrompts echoing raw config values; the agent narrating numbers it never read back; “changed the wrong thing” reports right after a human edit.
The fixOne resolver + one model-facing renderer for every state echo. Annotate oklch with hex, rem with px. For relative asks, show the whole ramp with the current rung marked ◀ — give the model a discrete neighbour to step to. Mark stale values in place ([SUPERSEDED — …]), never in a header. Wire tool inputs from run state so the model never carries them.
Episode 2

“The cheerful liar”

5 min

The sceneBrand changes apply roughly half the time. The agent reports success every time. The users think it’s moody. I think it’s the model. Everyone is wrong.

The twistThe specialists write their JSON in a fence — and then add a rationale after it. My regex assumed the fence ended the string. One slide, one regex, one red circle: the villain of this episode is seventeen characters of PHP. Decode failed → “intentional no-op” →

Done — your palette is ready.
“Completed” is a scheduler status, not a quality signal. Parse model output where a failure leaves a body — in the graph, where every step is a recorded job.
Field card 2 · model output
GotchaA NULL inside your code leaves no trace, and a validator that substitutes a default ([]) converts a mis-shaped op into a reported success. Models stringify JSON props, unquote numbers, and HTML-escape (& → &amp;) — strict type gates silently drop all of it.
Watch forRegexes over model output; is_array($x) ? $x : []; success text written before validation runs; “intermittent” bugs — type-dependent failures look random.
The fixParse in the workflow graph (tolerant JSON node) so a failure is a recorded job. Validate inside the sub-workflow so rejected: [{token, reason}] reaches the model before its closing prose. Repair the shapes models actually write at one choke point, then reject the rest by name (“Skipped: … Fix and re-send: …”). Decode HTML entities once, JSON-aware, at the tool boundary.

Episode 3

“Seeing double”

4 min

The sceneFrom the hosted demo: every page comes out with two heroes, two feature bands, two CTAs. Not a retry — two complete pages with different copy. The agent wrote it twice, on purpose, both times convinced it hadn’t.

The twistA scheduler race cloned a step; the clone re-read the conversation before the writes landed; the agent saw no page, so it built one. A stale read becomes a hallucination — the model was, again, right about what it was shown.

Done — your page is ready.
Exactly-once is an agent feature. One ledger line per tool call — “already invoked” must be a total answer.
Field card 3 · scheduling
GotchaAny step with two upstream triggers can be cloned by a late-routing predecessor; the clone reads older state and the model “forgets” what it just did. Cousin bug: per-execution identity (interrupt ids, approvals) copied into clones = stale approval — human-in-the-loop silently bypassed.
Watch forDoubled output with different copy; loop merges reading 2+ re-executing inputs; approval prompts that stop appearing after the first iteration.
The fixA run-scoped execution ledger keyed on tool_call_id — repeats emit no tool message, which is what stops the wave. Staleness gates phrased to fail open (stalled != true — fail-closed strands the agent after its first call). Dispatch every loop input from the same loopback. Never array_merge job metadata into clones.
Episode 4

“Whatscombe”

4 min

The sceneThe weather tool returns a blank card. The model’s call: args: []. And when the fallback kicked in, it geocoded the first word of “Whats the weather in Berlin” and cheerfully reported the weather in Whatscombe — a hamlet in Devon. Lovely weather, apparently.

The twistThe canvas editor writes location: '' into the node config by default — and an empty string counted as “the author pinned this”, which deletes the parameter from the schema the model sees. We’d blindfolded it and were grading its aim. Retracted upstream five days after it bit us — second cameo.

Done — here’s the weather.
Most “the agent called the tool wrong” bugs are your schema plumbing. The model can only fill the form you actually sent.
Field card 4 · tool schemas
GotchaConfig hides a parameter in both directions: an instance value pins it out of the schema ('' counts!), and a missing declaration (parameters: {}) drops the model’s args on arrival. Same symptom either way — and no-arg tools mask the defect. Bonus: gateways return tool calls under finish_reason: stop, and a parser keyed on the configured provider id drops the whole call.
Watch forargs: [] on a tool with required params; capabilities that only work when they take no arguments; “empty answer” turns with no exception anywhere.
The fixDebug from the schema the model actually received — it’s in the job trail — not the one you wrote. A param must be absent from config to be model-fillable. Parse responses by shape, never by configured provider id. A call whose args won’t parse is skipped, not dispatched empty — a recovered nothing beats a wrong action.
Episode 5

“Lost in translation”

5 min

The sceneBy now I’ve stopped trusting anecdotes — I built a ten-case live eval. Four cases won’t pass. “Make it blue” produces the same weird hand-computed colour every run, fails accessibility, and the agent narrates it as “AA-safe”. I blame the model. I have never been more sure.

The twistThe job trail shows the middle manager. The orchestrator reworded the user before delegating: “darker” became “step down its ramp” (obeyed literally — one rung); “blue” became “a blue hue” (the word “hue” flips the specialist into computing a literal). Both prompts already stated the right rule. The failure was the translation layer between two correct prompts. Fix: pass the user’s own words through. Four “model problems”, zero model changes.

The kickerI ship the release — and my own test fails the build, because it pinned the old prompt text. My test defended yesterday’s prompt against today’s. Annoying — and exactly right: prompt edits should cost something.

Done — set to an AA-safe blue.
Multi-agent hand-offs fail between two correct prompts. Test the seams in a live turn, against the job trail — green unit suites can’t see any of this.
Field card 5 · seams & proof
GotchaEvery hand-off is a lossy translation — the orchestrator’s paraphrase is a new prompt nobody reviewed. And “flaky” is just uncounted: 0/6 in one mode vs 6/8 in another is a diagnosis, not noise. A truncated call writes no usage row — the costliest failures are invisible in the cost report.
Watch forThe literal ask text in the trail (read what the specialist was actually asked, not what you meant); output caps set two levels down — a thinking model burns thousands of tokens before its first output token.
The fixPass the user’s own words through — the ask carries what and scope, the specialist owns how. Run a live-turn eval that asserts on the job trail; a key never observed must fail — silence is a finding, not a pass. expected_fail turns known-opens into counts and XPASSes the moment they’re fixed. Fingerprint the prompt sources so a cheap unit test goes red when you owe the expensive re-run. Pin load-bearing prompt substrings in tests, each needle annotated with why.

Act III — The bake-off

6 min

“After a year of episodes I stopped trusting my own war stories: the same dumb task — fetch a page, convert it, redact the competitors — eight architectures, four models, everything metered.” One slide for the eight contestants (the cold open was contestant B4). Then the only chart in the talk:

Tool takes the content517195
Tool takes a URL95

Same model, same prompt, same page, three draws — % of the document that survives.

“If the document travels through the model’s mouth, how much survives is a coin flip. Take it out of its mouth.”

The standings: the boring one wins — deterministic convert plus one LLM call, cheapest and best, and its only failure was loud. Then the lab’s own confession (30 s): one whole arm ran with an erased system prompt for hours; only a marker test caught it — put BANANA in the prompt and check the behaviour changes. 338 tokens of prompt bought 64 points of quality.

Close the act on the hierarchy, spoken not charted: structure, then caching, then — a distant third — model choice. (Caching gets that one word and nothing more — it’s a cost story, not a hallucination story; the full study lives at the QR.)

The variant with the least agency was the only one that never failed silently.
Field card 6 · from the lab
The fixTake the document out of the model’s mouth — tools take references (URL, id), not content: 18.5× fewer tokens, 6× cheaper, variance → 0. Pre-convert deterministically — HTML→Markdown before the model: 73,380 → 4,924 input tokens, one job instead of two. Marker-test your prompts — put BANANA in the system prompt and assert the behaviour changes; it’s the only reason I know one whole benchmark arm ran promptless. Order payloads stable-first (tools → system → history → the new turn) and keep per-request values out of the prefix — it’s what makes prompt caching possible later, and it costs nothing now.
37:00

The Field Guide

3 min

Twenty-second warm-up before the rules — the scar map: “Want to know where your agents hallucinate? Sort your prompts by size. Our typography specialist is 277 words. Our colour specialist is 1,561 — seventeen numbered rules. Same team, same product, 5.6× the size, because colour is where it lied to us. Prompt length is scar tissue. Here are our scars, as rules:”

“You’ve already seen all twelve — here they are on one screen.” Walked in 90 seconds; this slide holds through the confession reel and Q&A. The take-home slide, with the QR to the long-form notes.

Ground truth

  1. 01Never let a model re-type state. Wire it.
  2. 02Resolve aliases before they reach a prompt; annotate unreadable values (oklch → hex).
  3. 03Give relative asks a discrete neighbour — show the ramp, mark the rung.

Model output

  1. 04Parse where failure leaves a body — a NULL in PHP leaves no trace.
  2. 05Never substitute a default silently; reject by name, before the closing prose.
  3. 06Repair the shapes models actually write, once, at one choke point.

Tools & scheduling

  1. 07Exactly-once per tool call; staleness gates fail open.
  2. 08Debug the schema the model received, not the one you wrote.
  3. 09Parse responses by shape — configured ids lie.

Seams & proof

  1. 10Pass the user’s words through every hand-off.
  2. 11Eval live turns against the execution trail; make “flaky” a count.
  3. 12Prompts are config: version, pin, fingerprint — edits should cost something.

Still broken + the confession reel

2 min

Three real upstream issues, one line each: the prompt-eraser, the ReAct loop that re-sends its transcript uncached, prompt caching that’s unreachable through the OpenAI-compatible endpoint — zero cache hits in 330 metered calls, and the meter couldn’t even see a hit: on a cached call, input_tokens excludes the prefix, so a cache-blind meter under-bills by ~100%. Silent, plausible, wrong — same disease, cost edition. (The full caching study lives at the QR, not here.) Then, fast and self-deprecating: | tail ate my test failures for two phases · my eval’s first run reported $0.0000 because drush froze time at breakfast · the doc about keeping prompts fresh went stale · and our test docs record two environment variables that don’t exist — humans hallucinated them into blog posts, and we had to write down what isn’t true. Same disease, same fix.
